# Мотивация

Высокая нагрузка на систему влечет за собой потерю клиентов, что уже начало происходить.
Нужно быстро выявять проблемы и реагировать на них. Мониторинг позволит вовремя отслеживать 
узкие места, выявлять проблемы с нагрузкой, вовремя видеть ошибки и проблемы пользователей. 
Вовремя выявив и устранив проблему мы сумеем помочь пользователю, что оставит хорошее впечатление о компании.
Это, в свою очередь, повысит удовлетворенность пользователей. 

# Выбор подхода к мониторингу

Для CRM Четыре золотых сигнала от Google
Задержка — это время, которое уходит на доставку запроса по сети от отправителя к получателю.
Трафик — это показатель активности пользователей в вашем приложении.
Ошибки — это частота неудачных запросов. 
Насыщенность — здесь мы будем измерять память.

Для MES USE
Utilization (утилизация) — это среднее время, которое ресурс занят работой. Измеряется в процентах.
Saturation (насыщенность) — объём работы, которую ресурс не может выполнить и вынужден откладывать (например, в очередь), чтобы сохранять работоспособность.
Errors (ошибки) — количество ошибок.

Отслеживание взаимодействия сервисов
Number of dead-letter-exchange letters in RabbitMQ
Number of message in flight in RabbitMQ

Сервис MES
- Number of requests (RPS) for MES API - видеть количество запросов на сервиса
- Memory Utilisation for MES API - нужно понимать количествопотребляемой памяти 
- Number of HTTP 500 for MES API / Number of HTTP 200 for MES API - нужно вести статистику ошибок и положительных ответов
- Number of simultanious sessions for MES API - поможет выявить потенциальную нагрузку

Сервис CRM
- Memory Utilisation for CRM API - нужно понимать количествопотребляемой памяти 
- Number of requests (RPS) for MES API - видеть количество запросов на сервиса
- Number of simultanious sessions for CRM API - поможет выявить потенциальную нагрузку

Shop
Number of HTTP 200 for shop API / Number of HTTP 500 for shop API - нужно вести статистику ошибок и положительных ответов
Number of simultanious sessions for shop API -  поможет выявить потенциальную нагрузку

DB

Memory Utilisation for shop db instance - видим потенциальную нехватку памяти
Memory Utilisation for MES db instance - видим потенциальную нехватку памяти
Number of connections for shop db instance - нагрузка на память
Number of connections for MES db instance -  нагрузка на память
Size of shop db instance - видим возможности бд 
Size of MES db instance - видим возможности бд 

# План действий

- настройка Prometheus для сбора метрик
 По схеме:
 Time-Series база данных (TSDB), многомерная база данных временных рядов;
 Создаем компонент, который собирает метрики с агентов по модели pull (запрашивает метрики);
 Агенты-экспортёры, которые выполняются непосредственно на конкретных сервисах, собирая метрики в определённом формате.

 Настраиваем мертрики
 Индикаторы - количество запросов, количество ошибок, задержка
 Гистограмма - время запросов, методы


- настройка Grafana для визуализации
 Подключить Prometheus
 Настроить дашборды по всем показателям
