Закэшировать, для начала, стоит - MES, тк на систму MES больше всего жалоб из-за задержек

# Мотивация

Кэширование поможет нам избавиться от задержек в запросах и дать более быстрый доступ к данным
Для начала кэшировать будем самые уезвимые элементы систмы - MES, MES API, MES DB

# Предлагаемое решение

Предлагаю применить серверное кэширование. Данные по заказам часто меняются, записей в базу много.
БД тоже нагружена, что сильно влияет на время запроса. 

Для кэширования выберем паттерн Write-Through.
Асинхронные записи дают более быструю работ. К тому же реализация не столь высока по стоимости.

Инвалидация:
Инвалидация на основе изменений - например кэш будет меняться при изменении статусов заказов,
 при этом выполненые заказы можно удалять из кэша.
Инвалидация по ключу - так же можно применить для изменения информации по заказу. Подобная стратегия даст больше гибкости, при необходимости. 
Инвалидация, основанная на запросах - например создание нового заказа обновит список заказов (так же можно использовать инвалидацию на основе изменений)
Временную инвалидацию не вижу смысла использовать, тк изменение данных не привязанно к конкретным срокам
